## 二、记忆系统：现状

### 2.1 两套并存

| | 主记忆 | 塑料记忆 |
|---|---|---|
| 存哪 | `data/memory/<会话>/<QQ>.json` | `data/plastic-memory/chats/*.json` |
| 记什么 | 对某个人的印象 | 事件、约定、边界 |
| 分层 | 无 | ordinary / important / precious |
| 注入 | 每人 ≤7 条（私聊 +4）、总 3120 字符 | topK=4、总 1800 字符 |
| 检索 | 中文二元组重叠 + 新近度 | 重叠×3 + 强度×1.2 + 层级权重 + 新近度×0.3 |
| 反馈 | 无 | recallCount（注入时 +1）、useCount（手动 touch） |

### 2.2 实测数据（2026-11-11）

```
私聊塑料记忆：17 条（全部 active）
其中 9 条是同一件事："明天睁眼拍照"
useCount = 0 的有 17 条（100%）——只被注入，从未被"使用"
主记忆：仅 1 条，停在 10-21
群聊塑料记忆：1 条（已 archived）
```

### 2.3 六个具体弱点

**W1 去重失效**
同一件事（"明天睁眼拍照"）以不同措辞记了 9 条，强度全刷到 1.00。写入前没有相似度检测。

**W2 无语义检索**
全部基于字词重叠。"你上次说的那家店"和"那家店叫什么"对不上词就翻不到。
问"上周三我说了什么"这种时间检索，完全没有支持。

**W3 两套割裂**
主记忆几乎空（1 条），人物画像全靠塑料记忆承担；两段来源不同、口径不同，注入时各说各的。

**W4 只进不出**
`useCount=0` 说明没有任何"真的用到了"的信号；强度只靠"被注入"刷，导致
"经常被想起但没用"的记忆和"真正重要"的记忆无法区分。

**W5 主语混乱**
同一条记忆里混用"我 / 对方 / 对方"：
- "对方在公交车上靠着窗站着…"
- "对方 凌晨三点还没睡…"
注入后模型容易分不清"谁对谁做了什么"。

**W6 预算分配粗糙**
固定 topK=4、1800 字符。4 条普通记忆可能把 1 条珍贵边界记忆挤掉；
而私聊上下文有 17k token，记忆只占很小一块——**该给的地方没给够**。

## 三、上下文理解：现状

### 3.1 机制
- 无状态会话：每次只带「系统提示 + 96 条已读 + 未读 + 记忆 + 表情 + 日程」
- 实测单次请求约 17k token（近 3 天 112 次会话，最大 17,880 字符，0 次溢出）
- 日程是**虚构生活**，与你的真实状态（在公交上、电脑坏了）没有同步

### 3.2 四个弱点

**C1 元认知缺失**
她不知道自己"跑在你的电脑上"，所以"电脑坏了你就没法启动"只能当关系隐喻接。
设定里只有一句"你运行在事件驱动的桥接程序里"，讲的是消息怎么进来。

**C2 跨天就断片**
96 条窗口之外只能靠记忆；记忆弱 → "昨晚洗过澡，凌晨又说去洗漱"这类矛盾。
（跨夜注入已补上日程侧，聊天事实侧仍缺）

**C3 真实状态不同步**
你说"电脑坏了""在公交上""今天忙"，这些事实不会写进任何持久层；
下一轮她只有 96 条窗口，超出就忘，日程里也不会体现。

**C4 纠正依赖模型自觉**
"还没到站"这类纠正，现在靠提示词提醒（软约束），模型可能漏。
第一层规则+第二层提醒已加，第三层硬兜底没做。

## 四、解决方案

### P0：低成本、先止血（1~2 天）

| 项 | 做法 | 收益 |
|---|---|---|
| 记忆去重 | 写入前算相似度（二元组 Jaccard ≥0.6），命中就 `update` 旧条（合并 evidence、strength+0.1），不新增 | 9 条重复 → 1 条 |
| 主语规范 | 写入时强制"谁对谁做了什么"（我/对方），prompt 里说明 | 消除歧义 |
| 使用反馈 | 回复中真正引用某条时自动 `markUsed`，或注入后由 judge 判定 | useCount 不再恒 0 |
| 记忆预算 | 私聊 topK 4→8、字符 1800→3000 | 边界记忆不被挤掉 |
| 情景事实层 | 新增"今日事实"（24h TTL）：电脑坏了、在公交、今天忙……单独注入 | 解决 C3 |
| 元认知规则 | 一句"你是跑在他电脑上的 QQ-agent，平时不提，他拿电脑/关机开玩笑时顺着接" | 解决 C1 |

### P1：结构性改进（3~5 天）

| 项 | 做法 |
|---|---|
| 语义检索 | 接 embedding（本地 bge-small 或 API），混合检索：字面 + 向量 + 时间衰减 |
| 两套合一 | 主记忆的"人物画像"由塑料记忆按人聚合生成（偏好/边界/约定各一段），不再各存一份 |
| 约定回写 | followup 到期并完成后，回写一条记忆"已完成/未完成" |
| 纠正硬兜底 | 检测到纠正且日程不符 → 自动 replan，不等模型判断 |
| 识图链路 | 先 OCR 字幕 → `web_search` → 再回答，解决作品错认 |

### P2：长期（按需）

- **事件时间轴**：按天存"发生了什么"，支持"上周三""那次在车上"这类时间查询
- **每日记忆自审**：每天让模型整理当日记忆，合并重复、更新过时、降级没用到的
- **本地生图接入**：与记忆无关，但同属"减少外部依赖"的路线
